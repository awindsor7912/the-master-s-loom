# Learning Log — November 9, 2026

## Focus

Transitioning The Master's Loom from architectural planning into a working Next.js / React / TypeScript application while learning practical GitHub, VS Code, routing, and deployment workflows.

## Concepts learned

### 1. Separate application code from design documentation

The original `the-master-s-loom` repository retains the public project overview, architectural decisions, roadmap, and learning history. The `masters-loom-app` repository contains the Next.js application. This makes the documentation independently accessible and keeps implementation changes distinct from design notes.

### 2. Next.js App Router is file-system-based

- `src/app/page.tsx` maps to `/`.
- `src/app/campaigns/page.tsx` maps to `/campaigns`.
- `src/app/characters/page.tsx` maps to `/characters`.
- `src/app/sessions/page.tsx` maps to `/sessions`.

A missing route file produces a 404. A folder alone does not create a page.

### 3. Import aliases are anchored to configured paths

The import `@/components/workspace-nav` resolved to `src/components/workspace-nav.tsx`, not `src/app/components/workspace-nav.tsx`. A missing module may be a file placement issue rather than incorrect component code. Shared components are now stored at `src/components`.

### 4. Distinguish editor, shell, and application failures

- A VS Code `oom` error identifies a memory-related editor crash; a restart resolved the immediate problem without proving its root cause.
- PowerShell's script execution policy blocked the `npm.ps1` launcher, not the Next.js project. Running `npm.cmd run dev` worked without changing the machine's execution policy.
- A Next.js HTTP 500 with a module-not-found message indicated a compile/import failure.
- A Next.js HTTP 404 on `/sessions` meant the route had not yet been created.

Different failure messages point to different layers; checking terminal output before making changes prevents unnecessary resets and reinstalls.

### 5. GitHub and deployment workflow

Learned the distinction between local files, a Git commit, pushing to the remote GitHub repository, and deploying the web application. A successful local development run is not a production-build guarantee; `npm.cmd run build` is an important pre-push check. Vercel can build from the connected GitHub repository, but the deployment dashboard remains the source for confirming a particular deployment succeeded.

## Commands used

```powershell
npm.cmd run dev
npm.cmd run build
```

The `.cmd` form avoids PowerShell's attempt to execute `npm.ps1` under the current execution policy.
